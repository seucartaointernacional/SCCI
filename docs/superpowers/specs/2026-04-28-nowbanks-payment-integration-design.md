# NowBanks Payment Integration — Design Spec

**Date:** 2026-04-28
**Status:** Draft, awaiting user review
**Domain:** `https://seucartaointernacional.com`

## Goal

Replace the hardcoded fake PIX payload on the `/pagamento` page with a real PIX charge generated through the NowBanks API, and confirm the payment automatically when the customer pays — using a webhook from NowBanks as the source of truth and frontend polling for UX feedback.

## Non-goals

- Saque (withdrawals) — NowBanks supports it, but we have no flow that needs it.
- Saldo queries — not needed for this user-facing flow.
- Refunds, chargebacks, or admin reconciliation tooling — out of scope for this iteration.
- Removing the "Simular Pagamento" button — explicitly kept for now per user decision.

## Context

### Current state

- `Payment` (Prisma) has: `id, proposalId, valor, status, paidAt, createdAt`. No external transaction reference, no cached PIX payload.
- `POST /api/proposals/[id]/accept` creates a local `Payment` row (status `"aguardando"`) but does NOT call any payment provider.
- `/pagamento` page renders a **hardcoded fake** PIX payload (`PIX_PAYLOAD` constant in `src/app/pagamento/page.tsx`) and a fake QR generated by `qrcode.react` from that payload.
- `POST /api/payments/[id]/confirm` flips `status` to `"pago"` and sends a confirmation email. Today it is the only way the system marks a payment as paid, and it is called by the user-visible "Simular Pagamento" button.

### NowBanks API (relevant endpoints)

- Base URL: `https://api.nowbanks.com.br`
- `POST /v1/auth/login` with `client_id` + `client_secret` → JWT, `expires_in: 3600`
- `POST /v1/payments/deposit` (Bearer auth) with `amount`, `external_id`, optional `payer`, optional `clientCallbackUrl` → returns `{ transaction_id, status, pix_copy_paste, pix_qr_code, amount }`. `pix_qr_code` is a `data:image/png;base64,…` URL.
- `GET /v1/transactions/{transaction_id}` (Bearer auth) → returns `{ transaction_id, status, amount, created_at }`. Status values: `WAITING_PAYMENT`, `PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`, `CANCELED`, `REJECTED`, `RETIDO`.
- Webhook event `deposit.updated` payload: `{ id, type, data: { transaction_id, status, amount, external_id, provider, updated_at }, created_at }`. NowBanks signs the raw request body with HMAC-SHA256 (lowercase hex string) and sends it in the `X-Signature` header. The shared secret is configured in the NowBanks dashboard. Reference implementation in the docs uses PHP `hash_hmac('sha256', $payload, $secret)` and `hash_equals` for constant-time comparison.
- The webhook URL `https://seucartaointernacional.com/api/webhooks/nowbanks` is already registered in the NowBanks dashboard with a generated secret.

## Architecture

### Data flow (happy path)

```
Customer clicks "Aceitar Proposta" on /proposta
  → POST /api/proposals/:id/accept
      ├─ Update Proposal.status = "aceita"
      ├─ Create Payment (status "aguardando")
      └─ Call NowBanks createDeposit(amount=TAXA_IMPORTACAO, external_id=Payment.id)
          └─ Save transaction_id, pix_copy_paste, pix_qr_code on Payment

Customer arrives at /pagamento
  → GET /api/payments/:id  (returns valor, pix_copy_paste, pix_qr_code, status)
  → Page renders QR (PNG from base64) + copy-paste code
  → Page polls GET /api/payments/:id every 3s

Customer pays via PIX
  → NowBanks calls POST /api/webhooks/nowbanks
      ├─ Validate X-Signature HMAC-SHA256 against NOWBANKS_WEBHOOK_SECRET (fail-closed: reject if env missing)
      ├─ If event.type == "deposit.updated" AND data.status == "COMPLETED":
      │   ├─ Find Payment by id == data.external_id  (we set external_id = Payment.id when creating the deposit)
      │   ├─ Idempotency: if already "pago", return 200 OK (no-op)
      │   └─ Update Payment.status = "pago", Payment.paidAt = now
      └─ Send confirmation email (existing logic, moved from confirm route)

Frontend polling sees status flipped to "pago"
  → Redirect to /confirmacao
```

### Components

#### 1. `src/lib/nowbanks.ts` (new)

Single module wrapping the NowBanks API. Public functions:

- `getAccessToken(): Promise<string>` — caches JWT in module-level memory with expiry buffer (refresh 60s before `expires_in`). On Vercel serverless, cache lives per-instance (acceptable; worst case is one extra `/auth/login` per cold start).
- `createDeposit(params: { amount, externalId, payer?, callbackUrl }): Promise<{ transactionId, pixCopyPaste, pixQrCode, status }>` — POST `/v1/payments/deposit`.
- `getTransaction(transactionId: string): Promise<{ status, amount }>` — GET `/v1/transactions/{id}`. Used as a manual reconciliation fallback (admin tool later, not in this iteration).
- `verifyWebhookSignature(rawBody: string, signatureHeader: string): boolean` — computes `crypto.createHmac('sha256', secret).update(rawBody).digest('hex')` and compares to the header with `crypto.timingSafeEqual` (constant-time). Returns `false` if `NOWBANKS_WEBHOOK_SECRET` is not set or if buffer lengths differ.

Errors from NowBanks (RFC 7807 Problem Details) are caught and re-thrown as `NowBanksError` with `status` + `detail` for upstream handling.

#### 2. `prisma/schema.prisma` — add fields to `Payment`

```prisma
model Payment {
  id                       String    @id @default(cuid())
  proposalId               String    @unique
  proposal                 Proposal  @relation(fields: [proposalId], references: [id])
  valor                    Float
  status                   String    @default("aguardando")
  paidAt                   DateTime?
  nowbanksTransactionId    String?   @unique
  pixCopyPaste             String?
  pixQrCode                String?   // data: URL, ~5–10 KB; acceptable in Postgres TEXT
  createdAt                DateTime  @default(now())
}
```

Migration: `prisma migrate dev` locally, then `prisma migrate deploy` on Vercel build (already configured per recent commits).

#### 3. `src/app/api/proposals/[id]/accept/route.ts` — update

After the existing `prisma.$transaction([proposal.update, payment.create])`, call `nowbanks.createDeposit` and update the new `Payment` row with `nowbanksTransactionId`, `pixCopyPaste`, `pixQrCode`. If the NowBanks call fails, **roll back the Payment row** (delete it) and revert proposal status to `"pendente"`, then return 502 to the client. Reason: a Payment without a real PIX is a dead-end for the customer.

`payer.name` and `payer.document` come from the related `Lead`. `external_id` = `Payment.id`. `clientCallbackUrl` = `https://seucartaointernacional.com/api/webhooks/nowbanks` (from env `APP_BASE_URL`).

#### 4. `src/app/api/payments/[id]/route.ts` (new GET handler)

Returns `{ valor, pixCopyPaste, pixQrCode, status, paidAt }` for the frontend. No authentication — `id` is a cuid (not enumerable in practice) and the data is non-sensitive (PIX is one-time, tied to one paymentId). Existing routes (`/api/proposals/[id]`) follow the same model, so this matches the codebase pattern.

#### 5. `src/app/api/webhooks/nowbanks/route.ts` (new)

POST handler:
1. Read raw body (do not let Next.js parse it — HMAC must run on exact bytes).
2. Read `X-Signature` header.
3. If `NOWBANKS_WEBHOOK_SECRET` env is missing → log error, return 503 (fail-closed).
4. Verify HMAC. If invalid → return 401.
5. Parse JSON. If `type !== "deposit.updated"` → return 200 (we ignore other events).
6. Find Payment by `id = data.external_id` (we set `external_id = Payment.id` when calling `createDeposit`). If none → log warning, return 200 (ack so NowBanks does not retry forever; this happens for stale webhooks or transactions created outside this app).
7. If Payment.status is already `"pago"` → return 200 (idempotent).
8. If `data.status === "COMPLETED"` → update Payment, send email (move email logic from confirm route into a shared `lib/payment-finalize.ts` helper).
9. If `data.status` is `FAILED` / `CANCELED` / `REJECTED` → update Payment.status to `"falhou"` (no email).
10. Return 200.

#### 6. `src/app/api/payments/[id]/confirm/route.ts` — refactor

Keep the route (so the "Simular Pagamento" button keeps working in dev), but extract the actual finalization logic to `src/lib/payment-finalize.ts` and have both this route AND the webhook call it. Single source of truth for "mark a payment as paid + send email".

#### 7. `src/app/pagamento/page.tsx` — rewrite

- Drop the hardcoded `PIX_PAYLOAD`.
- On mount: `fetch('/api/payments/' + paymentId)`, store `pixCopyPaste` + `pixQrCode` in component state.
- Render the QR as `<img src={pixQrCode} />` (from API) instead of `<QRCodeSVG />` — NowBanks already provides the PNG. Remove the `qrcode.react` dependency if no other page uses it.
- Add a polling loop (every 3 seconds) that re-fetches `/api/payments/:id`. If `status === "pago"`, redirect to `/confirmacao`. Stop polling when redirected or when the 30-min timer hits zero.
- Keep the existing "Simular Pagamento" button (calls `/api/payments/:id/confirm` as today).
- Loading state while the initial fetch is in flight (skeleton or spinner where the QR will go).
- Error state if the fetch fails (rare, but: "Não foi possível carregar o pagamento. Tente novamente." + button to reload).

| Var | Purpose | Where to get it |
|---|---|---|

| `NOWBANKS_CLIENT_SECRET` | API auth | NowBanks panel → Chaves API (rotate the one shared in chat) |

All secrets stay in Vercel env, never in `.env` committed to git.

## Error handling

- **NowBanks createDeposit fails** (network, 5xx, 4xx): roll back Payment + proposal status, return 502 to user. UI shows generic "Não foi possível processar agora, tente novamente" with a retry button.
- **Webhook arrives for unknown transaction_id**: log warning, return 200 ack so NowBanks does not retry. Likely a stale webhook or a transaction created outside this app.
- **Webhook arrives with invalid HMAC**: return 401, log the attempt with IP. Do NOT update the database.
- **Webhook arrives with missing `NOWBANKS_WEBHOOK_SECRET` env**: return 503, log critical. NowBanks will retry; once env is set, retries will validate.
- **Frontend polling fails**: silently retry next tick. If the page is open past the 30-min timer, stop polling and show "QR expirado, gere novamente" (defer "gerar novamente" UI to a future iteration; for now, customer goes back and re-accepts the proposal).
- **Duplicate webhook for already-paid payment**: idempotent no-op, return 200.

## Testing

- **Unit:**
  - `nowbanks.verifyWebhookSignature` — valid signature, invalid signature, missing secret.
  - `nowbanks.getAccessToken` — caches token, refreshes near expiry.
  - `payment-finalize` — idempotency (calling twice is a no-op).
- **Integration (with mocked fetch):**
  - `accept` route creates Payment + calls NowBanks + saves PIX fields.
  - `accept` route rolls back when NowBanks errors.
  - Webhook route: valid signature + `COMPLETED` → marks paid + sends email.
  - Webhook route: invalid signature → 401, no DB write.
  - Webhook route: idempotent on duplicate.
- **Manual end-to-end:**
  - Use a low-value transaction (R$ 1,00) in production for the first real test.
  - Pay the QR with a real bank app, observe webhook landing, observe `/pagamento` page redirecting to `/confirmacao`.

No automated browser test in this iteration — Playwright/Cypress not configured in the project.

## Security considerations

1. **Client Secret rotation:** the secret shared in chat must be revoked and replaced before deploy. New value goes into Vercel env directly.
2. **HMAC validation:** fail-closed — webhook rejects everything if secret is missing.
3. **Webhook URL is public:** anyone can POST to `/api/webhooks/nowbanks`. Only HMAC-signed requests with valid signatures get processed.
4. **PIX QR is non-sensitive once generated** (it's a one-time payment instruction with the pre-set amount), so the unauthenticated `GET /api/payments/:id` is acceptable. CUID makes the ID non-enumerable.
5. **No logging of `pix_copy_paste` or full webhook bodies** in production to keep PII (CPF in `payer`) out of logs.
6. **The "Simular Pagamento" button remains** at the user's request. This is a known production risk: anyone can click it and mark their own payment as paid without paying. We accept this for now and will revisit.

## Rollout plan

1. Implement spec, run tests locally.
2. Push to a preview branch, deploy on Vercel preview env. Set NowBanks env vars in the preview environment only.
3. Configure NowBanks webhook URL temporarily to the Vercel preview domain. Run one R$ 1,00 end-to-end test.
4. Once verified, swap the NowBanks webhook URL to `https://seucartaointernacional.com/api/webhooks/nowbanks`, set production env vars, merge to master, deploy.
5. Run one more R$ 1,00 end-to-end test in production.
6. Monitor Vercel logs + Supabase Payment table for the next several real customers.
